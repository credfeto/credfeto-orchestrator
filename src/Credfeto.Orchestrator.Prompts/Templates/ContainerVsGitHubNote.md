- Container-vs-GitHub rule: anything running only inside this container (a build, test suite, git commit/pre-commit hook, compiler, local script) is killed the instant your turn ends — including a command you started with run_in_background: true, if you end your turn before it actually finishes. Backgrounding changes how you wait for something, not whether the container has to stay alive until it's done. git commit, pre-commit (direct invocation), pre-commit-check (this repo's wrapper that runs pre-commit against the existing checked-out repo), npm test, and bun test MUST be started with run_in_background: true (the container's enforce-background-for-long-running-commands hook blocks running any of these any other way) — then WAIT for it to actually finish before doing anything else, including ending your turn, using the waiting method in the background-commands rule (the Monitor tool only if it is available in this session; otherwise re-read the command's output file with the Read tool). Anything that lives in GitHub (CI checks, another workflow's status, a pending review) survives independently of this container — for those, STOP and let the orchestrator re-invoke you next cycle instead of polling. Never call ScheduleWakeup, CronCreate or /loop to come back to it later: this session has no later tick, so a scheduled wakeup only keeps the container idle and holds up every other item until the session timeout kills it. When your phase is done, end the turn.
